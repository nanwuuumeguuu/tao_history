制作ノート／2026-11-12 調査

起こらなかった経路

トポロジー、ヒルベルト空間、目的因。この三つを一本の映像にするための表現技法と、Claude から TouchDesigner・After Effects・Notch を動かす制作の組み方をまとめました。下の図は作品の中心になるショットを実際に計算したものです。

光は鏡のどの点でも反射してよいものとして、全経路に「回る矢印」を割り当てます。色は矢印の向き（位相）。濃い線は、隣どうしの矢印がそろって打ち消されずに残る経路です。
矢印を順につなぐと両端が渦を巻きます（コルニュ螺旋）。太い線が合計で、その長さの二乗が検出器の明るさです。
検出器の明るさ ×1.0

「鏡を削る」を入れると、逆向きの矢印を持つ経路だけが消え、端の経路まで光りはじめます。選ばれなかった経路は存在しなかったのではなく、互いに打ち消し合っていただけだ、という絵になります。この計算は 20 行ほどの GLSL でそのまま TouchDesigner に移せます（ショット A）。

いま可能なこと

2026 年 11 月時点で、Claude からアプリを直接操作できる範囲はツールごとに大きく違います。「確認」の列は、今回リポジトリやマニュアルを直接読めたかどうかです。

組み方の結論。絵づくりの主軸は TouchDesigner（公式 MCP があり、作る→見る→直すの往復ができる）。Notch は Claude が書いたシェーダーを差し込む仕上げ用。After Effects は合成と文字、Premiere は Claude が書いたタイムラインファイルを読み込むだけにすると、壊れやすい部分を避けられます。

連携の構成

公開されている完成度の高い事例（OpenMontage、video-use、claude-faceless-shorts-creator など）に共通するのは、プログラムではなくエージェント自身が進行役になり、段階ごとに決まった形式のファイルを残していく作りです。それをこの作品向けに置き換えると次のようになります。

flowchart TD
  H["人：主題・承認・最終の目と耳"] --> C["Claude Code（進行役）"]
  C --> S["script.json 台本"]
  S --> P["scene_plan.json ショット表"]
  P --> TD["TouchDesigner（TDMCP）シェーダーと粒子"]
  P --> BL["Blender（MCP）曲面と分岐メッシュ"]
  P --> NO["Notch（.fx を書く＋OSC）"]
  S --> VO["ElevenLabs 朗読と単語の時刻"]
  TD --> R["renders/ 連番画像"]
  BL --> R
  NO --> R
  R --> AE["After Effects（MCP）合成と文字"]
  VO --> OT["timeline.otio"]
  AE --> OT
  OT --> PR["Premiere / Resolve 読み込みと書き出し"]
  R -. 静止画を見て直す .-> C
  • 台本とショット表が唯一の正。どのアプリの作業も、この二つのファイルの ID と秒数を参照します。
  • 朗読を先に作り、絵は実測した音の長さに合わせる。Manim 系の事例で定着しているやり方です。
  • 見られないものは測る。Claude は音を聴けないので、音量は ffmpeg -af ebur128 の数値で確認し、最終判断は人の耳に残します。
  • 直す回数に上限を置く。事例では自己評価 3 回まで、レビュー 2 往復までが目安になっています。

映像候補とレシピ

八つのショット候補です。A〜C が主題の核、D〜H は章をつなぐ素材です。技法の対応づけは調査した資料をもとに私が組み立てたもので、TouchDesigner や Notch 用の既製プロジェクトはどの主題でも見つかりませんでした。

A　鏡とすべての経路

目的因の章の中心／上の図の本番版
意味
光は「最短の道を知っていた」ように見える。実際には全経路の矢印の合計で、残るのが最短時間の近くだけ。ファインマンの QED 講義の鏡の話です。
技法
経路ごとの位相を色相にした細線を加算合成。隣接経路の矢印のそろい具合を明るさにする。鏡の下に小さな時計の列、画面の隅にコルニュ螺旋。
数式
経路長 L(x)=r1+r2、矢印 exp(i·k·L)、k=2π/λ。L'(x)=0 が入射角＝反射角。削る条件は cos(k·L−φ0)>0 の点だけ残す。波長は鏡の長さの 1/30〜1/100 に誇張すると渦が見えます。
作り方
TouchDesigner の GLSL TOP 一枚で場全体（検出器の位置＝画素）を計算し、経路の線は別の GLSL TOP か instancing で重ねる。波長を 3 つ以上で計算して RGB に足すと、削った鏡が虹を出します。
再利用元
既製のシェーダーは見つからず。参考は Taylor ほか「Teaching Feynman's sum-over-paths quantum theory」。
// GLSL TOP 用の核。uniform: S, D(=画素でも可), k, wt, a, b, scrape, phi0
vec2 A = vec2(0.);
float dx = (b - a) / float(N);
for (int j = 0; j < N; j++) {
  float x  = mix(a, b, (float(j) + .5) / float(N));
  float r1 = length(vec2(x - S.x, S.y)), r2 = length(vec2(x - D.x, D.y));
  float L  = r1 + r2, dL = (x - S.x)/r1 + (x - D.x)/r2;
  float z  = .5 * k * dL * dx;
  float w  = dx * (abs(z) < 1e-4 ? 1. : sin(z)/z);        // 区間内の位相変化を補正
  float keep = scrape ? step(0., cos(k*L - phi0)) : 1.;    // 鏡を削る
  A += keep * w * vec2(cos(k*L - wt), sin(k*L - wt));
}
float I = dot(A, A);   // 明るさ。経路 j の色相は fract((k*L - wt)/6.2831853)

B　終わりから来る波

「未来が経路を決める」をそのまま絵にする
意味
光源から広がる波と、検出器から時間を逆向きにさかのぼる波。二つが重なるところだけが光る。二状態ベクトル形式や交流解釈の図式です。
技法
2D のシュレーディンガー方程式（または波動方程式）を二回解き、片方を逆再生。明るさ＝ψ前 × ψ後* の絶対値、色相＝位相差。
作り方
GLSL TOP と Feedback TOP の往復計算。rgba32float を使う（8bit は 0〜1 に切られる）。逆向きの波は別に連番で書き出して逆再生するのが簡単です。
再利用元
qmsolve（BSD-3、Python で先に検証）、QM-Simulator-2D（WebGL、ライセンス種別は未確認）、解説 Shaders of Schrödinger。
注意
逆因果は解釈の一つで、実験で確かめられた事実ではありません。ナレーションは「〜と読むこともできる」の形に。

C　歩く人の分岐樹

添付の参考動画 2 本の技法
見たもの
白地に、歩く人物の残像が帯になり、その帯が枝分かれして樹になる。人物にだけ銅色が残り、軌跡は墨色。引きでは樹、寄りでは連続写真に見える。
意味
多世界の分岐、あるいは選ばなかった人生。実現した枝だけ濃く、他は消さずに薄く残す。
技法
歩行アニメーションを時間をずらして曲線上に大量に複製する（クロノフォトグラフィ）。枝の太さ＝振幅の二乗、分岐点で複製が二手に分かれる。
作り方
① Blender で分岐曲線を生成（再帰 or L-system を Python で）。② 歩行素材は自分で撮った横歩きを切り抜くか、ライセンスを確認した歩行アニメを使う。③ TouchDesigner の Geometry COMP instancing で、曲線上の位置と時間オフセットを各コピーに渡す。④ 乗算合成で白地に重ねる。After Effects だけで作るなら、パスに沿わせた人物レイヤーに「エコー」。
発展
ショット A の経路の束をこの樹に置き換えると、人の歩みと光の経路が同じ絵になります。

D　ホップ・ファイブレーション

トポロジーの章の導入
意味
球面の一点が、四次元の球の中の一つの円に対応する。どの二つの円も必ず一度だけ絡む。「一つの状態の背後にある位相の輪」としてヒルベルト空間の章にもつながります（量子ビットの状態空間がこの構造です）。
数式
q(t)=(cos(θ/2)·e^{i(t+φ)/2}, sin(θ/2)·e^{i(t−φ)/2}) を (x,y,z)/(1−w) で投影。
作り方
円をチューブとして instancing。色相＝球面上の経度。球面上の点を緯線や螺旋に沿って動かし、投影前に四次元回転（xw 面と yz 面）をかける。
再利用元
mwalczyk/hopf（CC BY 4.0、.obj 書き出し可）、Niles Johnson の制作ノート。

E　波束と交差しない流線

ヒルベルト空間の章の中心
意味
波は二つのスリットの両方を通る。粒子の流線（ボーム軌道）は決して交わらず、編まれた髪のようになる。
技法
色相＝位相、明度＝確率密度。粒子は v=(ħ/m)·Im(∇ψ/ψ) で流し、Feedback で軌跡を残す。
作り方
B と同じ計算基盤。粒子は GLSL POP か、位置を持つテクスチャの往復計算。
再利用元
double-slit-2d-schrodinger（MIT）、qmsolve。

F　双曲空間と四次元多胞体

空間そのものが違う、という体感
技法
2D は円反転のくり返しで画素を基本領域に折りたたむ。3D は測地線に沿ったレイマーチング。多胞体は頂点を四次元で回して立体射影し、辺を円弧で描く。
作り方
TouchDesigner なら RayTK（CC BY 4.0）。Notch なら Procedural ノード群と Procedural Raytracer が SDF のレイマーチングに当たります。
再利用元
roice3/Honeycombs（MIT）、論文 Ray-marching Thurston geometries。non-euclidean_VR は GPL v3 なので、組み込むと作品のコードも同じ条件になります。

G　リーマン面と被覆

一周しても元に戻らない場所
技法
複素関数の定義域彩色（色相＝偏角、明度＝絶対値の対数の等高線）。log z は螺旋階段（ヘリコイド）にして、カメラが分岐点を回りながら階を上がる。
作り方
Blender でパラメトリック曲面を Python 生成、または GLSL でレイマーチ。クラインの壺は閉じた距離関数が知られていないので、メッシュで作ります。
使いどころ
「同じ場所に戻ったのに別の層にいる」は、起こらなかった可能性の世界の比喩として使えます。

H　ブロッホ球と色が抜ける瞬間

重ね合わせが失われる場面
技法
状態ベクトルが球面上に軌跡を残して回る。デコヒーレンスはベクトルが球の内側へ縮むこと。画面全体では位相の色相が抜けて灰色になり、干渉縞が消える。
作り方
数値は QuTiP（BSD）で出して CSV にし、TouchDesigner か After Effects に読み込む。色抜きは全ショット共通の HSV 調整に一つのパラメータとして持たせます。

出力形態ごとの向き不向き

形態向くショット作り方の違い
縦型の短尺（15〜60 秒）A か C を一つだけ1080×1920。問い一つ、絵一つ。TouchDesigner から連番で書き出し、文字は After Effects
横型の作品（3〜8 分）D → E → A → B → C の順朗読を先に確定。ショット単位でオフライン書き出し、OTIO で編集へ
展示・リアルタイムA・E・F（操作できる計算）観客の位置を検出器 D に割り当てると、A は「見る場所が経路を決める」体験になります。仕上げに Notch を使うなら公開パラメータを OSC で駆動

一本の完成形と台本

横型・約 3 分の構成例です。台本は私が書いた叩き台で、秒数は朗読を合成して実測した値に置き換える前提です。日本語の朗読は 1 分あたり 300 字前後を目安に置き、全体の 2〜3 割を無音にしています（英語の目安 125〜150 語／分から私が置き換えた数字です）。

事実の扱いについて三点。

  • 目的因はアリストテレスの学説です。ソクラテスを登場させるなら、プラトン『パイドン』で「最善であること」による説明を求める場面が接点になります。
  • 「光がすべての経路を通る」は計算の描像で、実在の主張としては異論があります。Veritasium の動画の回折格子の実演にも反論が出ています（Looking Glass Universe）。台本では「計算の上では」としています。
  • 最小作用を目的論と読むのはモーペルテュイ以来の伝統ですが、現代の物理哲学では因果ではない制約と読む立場が有力です（Glick 2023）。

制作モデル

思いつきの対話から緻密な作品へ持っていくには、Claude に毎回同じ手順を踏ませる枠が要ります。公開事例の共通項をこの作品用に組み直しました。

film/

CLAUDE.md の例

# この作品の規則
- 作業は必ず scene_plan.json の 1 ショットを対象にする。ID と秒数を勝手に変えない。
- 朗読が先。絵の長さは audio/ の実測時刻に合わせる。
- TouchDesigner
  - 既存の知識を信用しない。オペレータを作る前に get_docs / get_help で確認する。
  - 作ったら get_errors（警告も読む）→ view_operator で画像を見る。黒い画面はシェーダーのエラーを疑う。
  - 時刻は absTime.seconds を uniform で渡す。計算用テクスチャは rgba32float。
  - Feedback TOP は先に作り、解像度を明示し、ループは最後に閉じる。
  - 作り直す前に同名オペレータを消す。
- After Effects
  - ExtendScript は ES3（var と function のみ）。alert を出さない。beginUndoGroup で囲む。
  - エフェクトは matchName、フォントは PostScript 名。呼び出しは直列。
- 見る→直すは 1 ショット 3 回まで。越えたら状況を書いて止まる。
- 物理の記述は physics_claims に書き、fact-checker の確認を通す。解釈は断定しない。
- library/ に入れてよいのは自作か、catalog.json にライセンスを書けるものだけ。
- 有料の生成を呼ぶ前に、見込みの費用を書いて承認を待つ。

役割の分け方

役割担当入力 → 出力

# ショット A を TouchDesigner に作る
scene_plan.json の A1 を作ります。まず project_info と td-general スキルで現状を確認してください。
/project1/A_mirror に次を作ります。
1. GLSL TOP「field」1920x1080, rgba32float。shots/A_mirror/shader.glsl を Pixel Shader に入れる。
   uniform: uS(vec2), uK(float), uTime(float=absTime.seconds), uScrape(float), uPhi0(float)
   検出器の位置は画素座標。鏡は y=0、x は -1〜1。
2. 経路の線は別の GLSL TOP「paths」。n_paths 本、色相=位相、明るさ=隣接 9 本の矢印の合計の長さ。
3. Composite TOP で加算し、Null TOP「out」で終える。
各段のあと get_errors を読み、view_operator で out を見せてください。
acceptance を満たさない点を自分で挙げてから直すこと。3 回で止まってください。
# 事実確認（別コンテキストのサブエージェント）
あなたは物理と哲学史の校閲者です。script.json と scene_plan.json の physics_claims を読み、
(1) 誤り (2) 解釈を事実として述べている箇所 (3) 人名・年代の誤り を、該当 ID と直し案つきで挙げてください。
確かめられないものは「未確認」と書き、推測で埋めないでください。
# 批評（制作過程を見ていないサブエージェント）
shots/A_mirror/stills/ の 3 枚と、そのショットの description・acceptance だけを見てください。
style.md に反する点、主題が読み取れない点、画面の端で切れている要素を、
重大／提案／些細に分けて挙げてください。直し方は座標や数値で書いてください。
# Notch 用のカスタムシェーダー
Notch のマニュアル MCP で「Custom Shader Post Effect」と「working with custom shaders」を検索し、
生成された雛形 mirror.fx を読んでから、shots/A_mirror/shader.glsl を HLSL に移してください。
波長・削る量・時間を propertyName / propertyMin / propertyMax 付きで公開します。
保存すると Notch が再読込するので、変更は 1 か所ずつにしてください。
# タイムライン
audio/words.json の実測時刻と scene_plan.json から timeline.otio を書いてください。
映像は renders/<id>/ の連番、音声は audio/vo.wav。target_url に file:// を付けないこと。
書いたら各クリップの開始・終了を表で見せ、台本の区間とのずれが 0.2 秒を超える所を挙げてください。
